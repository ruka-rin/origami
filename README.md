# origami

折纸谜题的设计工具：把一份**母版字符串**（或普通文本）变成折痕图、方形 CP 与折叠成品，
并保证结果与题面给出的参考图形一致。

- **桌面端**（Avalonia）：文本框输入文字自动生成母版，六种视图（长条/方形 × 折痕图/成品/原子片）实时预览，
  可导出 SVG / PNG，方向可旋转与镜像。
- **命令行**（`origami`）：母版 → 折痕图 / 方形 CP / 折叠成品 / 反向推导，批处理与回归核对用。
- **核心库**（`Origami.Core`）：纯计算，无界面依赖。

---

## 快速上手

```bash
dotnet build Origami.slnx -c Release      # 构建
dotnet test  tests/Origami.Tests          # 跑全部测试（Debug 与 Release 都应全绿）
dotnet run --project src/Origami.Desktop # 启动桌面端
```

命令行：

```bash
# 普通文本 -> 母版串（会带上开头的方向标记）
dotnet run --project src/Origami.Cli -c Release -- text -t KRENIO

# 母版 -> 全部产物（长条/方形折痕图 + 两种折叠成品）
dotnet run --project src/Origami.Cli -c Release -- build -m "/....|../\\.|.//.\\./.../\\./." -o out/

# 导出单个视图
dotnet run --project src/Origami.Cli -c Release -- export -m "<母版>" --view 方形成品 --png -o out/a.png
```

`origami --help` 列出全部子命令。

## 母版字符串格式

母版描述的是**一条连续长条纸带**上的折痕，从左往右读：

| 符号 | 含义 |
| --- | --- |
| `/` `\` | 该格内的一条对角折痕，各占一格 |
| `.` | 无折痕的素格 |
| `\|` | 竖直折痕，**不占格**，插在两格之间 |

坐标为数学坐标（y 向上），格 `k` 占 `[k,k+1]×[0,1]`。没有 `|` 的格边界上根本没有线 ——
纸是连续的，只有 `|` 才是竖直折痕。

### 开头的方向标记

母版串**开头**可以带一段方向标记（正文里再出现 `@`/`#` 即为非法字符）：

| 记号 | 含义 |
| --- | --- |
| `@` | 成品顺时针转 90°，取个数对 4 取模。**只影响画布**，不改折痕。 |
| `#` | 整条纸带**上下翻转**：所有 `/` 与 `\` 互换。**改的是折痕本身**，铺排与折叠都跟着变。 |

例：`@@#..\.../.\.`

标记是必要的，因为「折痕的方向」与「折好后该怎么看」是两件事。旧参考实现只收文本，
能在内部悄悄把成品转到正位再画出来；拆成「文本 → 母版串」这一步之后，这层信息必须
显式记下来，否则母版串单独使用时无法自动摆正。

标记的取值由 `LegacyMarkParityTests` 逐字模对照参考实现钉死，规律是：
`#` 当且仅当字模编码含 x=0 竖折痕；带 `#` 时 `@` 的个数比字模 rotate 多 2
（*左右翻转 = 上下翻转 ∘ 转 180°*）。

**摆正只作用于成品与原子片视图。** 折痕图是数据，不跟着转 —— 方向信息会以
`data-marks` 写进导出的 SVG，导回来时补回母版串。

## 目录结构

```
src/Origami.Core        纯计算库：几何、折叠、铺排、SVG / PNG
src/Origami.Desktop     Avalonia 桌面端（程序集名 origami-ui）
src/Origami.Cli         命令行工具（程序集名 origami）
tests/Origami.Tests     xunit 测试，含 Avalonia.Headless 无头 UI 测试
```

`tests/Origami.Tests/legacy_*.json` 是**一致性基准**：由 Node 直接运行旧参考实现
（`旧的参考代码/strip.js`、`index.js`）导出，不含手工转录。测试比对的是两边的运行时真实值。

> `tools/` 不在版本控制内（其中的脚本用于重新生成上述基准数据，需要旧参考实现才能跑）。

## 一致性核对

本项目大量结论来自与旧参考实现的逐顶点比对，而不是「看起来对」：

- `ShapeMatch.Match` —— 把两边都归一化后栅格化成 72×72 掩码求 IoU，
  对「面片划分方式不同」「纸带高度差 2 倍」「坐标方向相反」都免疫；
- 朝向另有长宽比判据 —— IoU 会把宽高各自归一化，**看不出差 90° 的旋转**；
- 母版标记表（`LegacyMarkParityTests`）逐字模钉死，带标记的成品与旧实现重合度 ≥ 0.99。
